## 3. Message bus + module lifecycle

Every module is just a `Module` trait impl whose lifecycle hooks are driven by the kernel. Bus messages flow through `MessageBus` as `Envelope { source, correlation_id, timestamp, message }`.

```mermaid
sequenceDiagram
    autonumber
    actor Caller as Caller (your code)
    participant Bus as MessageBus
    participant MM as ModuleManager
    participant Mod as Module impl<br/>(browser / mirror / llm / …)

    Caller->>MM: register_native(module)
    MM->>Mod: init(bus.clone())
    Note over Mod: module subscribes to bus,<br/>spawns listener task
    Caller->>MM: start("module_id")
    MM->>Mod: start()
    MM-->>Bus: emit Event::ModuleStarted

    rect rgb(40, 60, 90)
        Note over Caller,Mod: Steady state — agent loop
        Caller->>Bus: send_command(Invoke{module_id, method, payload})
        Bus->>Mod: envelope routed to subscriber
        Mod->>Mod: dispatch(method, payload)
        Mod-->>Bus: emit Event::Custom{kind: "<method>.ok", payload}
        Bus-->>Caller: subscriber sees event
    end

    Caller->>MM: stop("module_id")
    MM->>Mod: stop() (abort listener)
    MM-->>Bus: emit Event::ModuleStopped
```

### Lifecycle state machine

```mermaid
stateDiagram-v2
    [*] --> Loaded: register_native()
    Loaded --> Starting: start()
    Starting --> Running: start() OK
    Starting --> Failed: start() Err
    Running --> Stopping: stop()
    Stopping --> Stopped: stop() OK
    Stopping --> Failed: stop() Err
    Stopped --> Starting: start() again<br/>(idempotent)
    Failed --> [*]: unload()
    Stopped --> [*]: unload()
```

## 5. MCP integration — Claude Code talking to Rust Oxide

How an external agent runtime (Claude Code, Cursor, any MCP client) invokes Rust Oxide capabilities.

```mermaid
sequenceDiagram
    autonumber
    actor User as User in Claude Code
    participant CC as Claude Code (MCP client)
    participant LAU as mcp-launcher<br/>(your binary)
    participant Bus as oxide-k bus
    participant BR as BrowserModule
    participant MIR as MirrorModule

    User->>CC: "scrape example.com<br/>and store it"
    CC->>LAU: JSON-RPC initialize / tools/list (stdin)
    LAU-->>CC: tool descriptors<br/>(browser.navigate, mirror.query, …)

    CC->>LAU: tools/call {name: "browser.navigate", arguments: {url}}
    LAU->>Bus: Command::Invoke{module_id:"browser", method:"navigate"}
    Bus->>BR: routed envelope
    BR->>BR: backend.navigate(url)
    BR-->>Bus: Event::Custom{kind:"navigate.ok"}
    Bus-->>LAU: subscriber sees event
    LAU-->>CC: JSON-RPC result {content, structuredContent, isError:false}
    CC-->>User: tool result rendered

    Note over CC,MIR: Same flow repeats for mirror.query,<br/>browser.extract, etc.
```

## 6. Inter-agent fabric — `oxide-mesh` topology

Multiple agents federating across processes / hosts.

```mermaid
flowchart LR
    classDef agent fill:#1e3a8a,stroke:#60a5fa,color:#dbeafe;
    classDef trans fill:#581c87,stroke:#c084fc,color:#faf5ff;
    classDef state fill:#14532d,stroke:#4ade80,color:#dcfce7;

    subgraph Host1["Host A"]
        A1[agent-alpha<br/>browser capability]:::agent
        A2[agent-beta<br/>mirror capability]:::agent
        LM1[(LocalMesh<br/>mpsc channels)]:::trans
        CRDT1[GSet / LwwRegister<br/>/ PnCounter]:::state
        A1 <--> LM1
        A2 <--> LM1
        LM1 <--> CRDT1
    end

    subgraph Host2["Host B"]
        A3[agent-gamma<br/>llm capability]:::agent
        LM2[(LocalMesh)]:::trans
        CRDT2[same CRDT shape]:::state
        A3 <--> LM2
        LM2 <--> CRDT2
    end

    LM1 <-->|"TcpMesh<br/>JSON-line frames"| LM2
    CRDT1 <-.->|"merge on broadcast"| CRDT2
```

Messages flow as `PeerMessage::{Hello, Broadcast, Direct, Task, Result}`. CRDTs converge on every merge regardless of arrival order.

## Reading these diagrams

- Boxes coloured by **role**, not by depth — kernel / Layer 2 / Layer 3 / transport.
- Solid arrows = synchronous calls or direct deps.
- Dashed arrows = bus events or async fan-out.
- Cylinders = persistent stores (SQLite tables, in-memory graphs, XAI log).

For the source-of-truth tables (every bus method, every module's payload shape), see the per-crate docs at `cargo doc --workspace --no-deps --open` and the [`USAGE.md`](../USAGE.md) recipes.
